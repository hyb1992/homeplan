# 우리집 매수계획

집을 사기 전과 산 뒤의 **현금·대출·생활비를 날짜별로 살펴보는 앱**입니다. 매수 일정, 자금 입금일, 대출 상환과 출산·휴직 계획을 바꿔 잔고가 부족해지는 시점을 확인할 수 있습니다.

이 안내는 **0.7.1 기준**입니다. 버전별 변경사항은 [릴리스 노트](RELEASE_NOTES.md), 실제 게시된 배포본은 [Releases](https://github.com/hyb1992/homeplan/releases)에서 확인하세요.

## 바로 사용하기

| 사용 방식 | 시작 방법 | 데이터 저장 위치 |
| --- | --- | --- |
| 웹 | [브라우저에서 열기](https://hyb1992.github.io/homeplan/) | 사용하는 브라우저 안 |
| Windows 앱 | [Windows ZIP 다운로드](https://github.com/hyb1992/homeplan/releases/latest/download/HomePlan-Windows-x64.zip) | 앱의 `data` 폴더 |

**일반 사용자는 Python·uv 설치나 명령어 실행이 필요 없습니다.**

### Windows 앱

1. ZIP **전체**를 문서나 바탕화면의 새 폴더에 압축 해제합니다.
2. `HomePlan` 폴더 안의 **`HomePlan.exe`**를 실행합니다. `_internal` 폴더도 함께 있어야 합니다.
3. 처음 열리는 새 계획에서 본인의 현금·소득·생활비·매수 일정을 입력합니다.
4. 입력을 바꾼 뒤 **다시 계산 → 변경사항 저장 → 미리보기 확인**으로 보관합니다.

Windows 64비트용이며 Edge 또는 Chrome으로 앱 창을 엽니다. 최초 계획은 비어 있고, **가상 테스트**는 별도의 예시입니다. 앱 전용 창이 열리지 않으면 함께 제공하는 **기본 브라우저로 실행.cmd**를 사용할 수 있습니다.

### 웹

[웹 주소](https://hyb1992.github.io/homeplan/)를 열고 새 계획을 입력합니다. 첫 실행에는 계산 환경을 내려받으므로 인터넷이 필요하며 처음 화면이 준비되는 데 시간이 걸릴 수 있습니다.

금융 입력은 서버에 전송하지 않고 브라우저 안에서 계산·저장합니다. 사이트 데이터를 삭제하면 저장한 계획도 지워지므로 **입력값 내보내기**로 별도 보관하세요. 다른 기기·브라우저·Windows 앱과 자동 동기화하지 않으며 JSON 내보내기·가져오기로 옮길 수 있습니다.

## 어떤 화면에서 무엇을 하나요?

| 메뉴 | 주요 기능 |
| --- | --- |
| 매수계획 | 매물·계약금·중도금·잔금·입주·퇴거 일정, 일별 현금 그래프, 부족 조건과 최대 매수가 |
| 계약·지급 | 약정금부터 허가 신청·승인·본계약·입주까지 진행 단계, 실제 지급 내역과 남은 매매대금 |
| 매수 비용 | 취득세·중개보수·법무·등기·수리·가전·이사 비용과 지급 시점 |
| 우리 자금 | 자금 빌더, 이름에 맞는 유형 추천, 변동자산의 보수적·공격적 금액, 유형별 도넛 그래프 |
| 부모님 지원 | 증여·가족 차입의 금액·입금일·확정 여부, 중도금일·잔금일 연결 |
| 대출·가계 | 대출 조건·기간별 생활비와 주거비·양육비·추가 상환·지출 한도 |
| 출산·휴직 | 출산휴가·부부 육아휴직·복직·급여 보전과 지급 지연 |
| 대출 상환표 | 정기 납부·추가 상환의 원금·이자·수수료·잔액, 연도 필터와 CSV |
| 은행 상담 | 은행별 상담 조건 추가·수정·삭제와 계산에 적용 |
| 날짜별 현금 | 특정 날짜의 보유 현금·남은 빚·입출금과 월별 원장 |

상단에서 새 계획 만들기, 계획 복사·비교, 상세 설정, 백업·복구, JSON 가져오기와 계산 기준·출처를 사용할 수 있습니다. **0.6.2부터 엑셀 업로드·가져오기 화면은 제거했습니다.** 엑셀을 저장 DB로 사용하지 않습니다.

## 약정금부터 입주까지 진행 상황과 지급 기록

**계약·지급 → 약정·계약 기록 시작**에서 매수 중인 집과 예정 매매가·계약금 총액·중도금을 확인합니다. **약정·허가 준비**를 선택하면 본계약일 없이 시작할 수 있습니다. 허가 단계를 사용하면 **약정금 지급 → 토지거래허가 신청 → 승인 → 본계약 체결 → 중도금 → 잔금·등기 → 입주** 순서로 기록합니다. 단계마다 예정일·실제 완료일·상태·메모를 남기고, 필요한 단계를 추가하거나 해당 없음으로 바꿀 수 있습니다.

허가 대상과 절차는 해당 매물 기준으로 확인하세요. [서울시 토지거래계약허가 안내](https://land.seoul.go.kr/land/other/contractGuide.do)를 참고할 수 있습니다. 앱은 지역 이름으로 허가 필요 여부나 약정의 효력을 판정하지 않습니다.

**약정금 기록**에는 실제 이체한 날짜·금액·지불한 사람·받는 곳·메모를 입력합니다. 약정금 기준액과 실제 지급 기록은 별개입니다. **약정금이 본계약 계약금 총액에 포함됩니다**를 선택하면 약정금과 추가 계약금을 합쳐 계약금 총액과 비교하며, 총지급액은 한 번만 집계합니다. 포함하지 않으면 정산 전 별도 보관금으로 표시하고 집값 지급액이나 부대비용에는 넣지 않습니다. 본계약 후 상태와 실제 본계약일을 바꾸거나 본계약 단계를 완료하면 됩니다.

**지급 기록**에는 나눠 낸 계약금·중도금·잔금도 건별로 등록할 수 있습니다. 집값 지급액과 취득세·중개보수 등 부대비용을 구분하며, 남은 매매대금은 계약 매매가에서 집값 지급액을 뺀 값입니다. 계약금에 포함하는 약정금도 집값 지급액에 반영됩니다.

기존 기록은 **진행 정보 수정**에서 허가 단계를 추가할 수 있습니다. 작성한 단계·지급 내역은 유지되며, 허가 단계 사용을 해제해도 이미 작성한 단계는 삭제하지 않습니다. 기록은 이 집에 고정되므로 다른 검토 매물을 골라도 유지됩니다.

진행 단계 완료가 지급 기록을 자동 생성하지 않으며, 실제 지급 기록은 **기존 예상 현금 원장에서 다시 차감하지 않습니다.** 계약 조건을 예상 현금에 반영하려면 매수계획도 별도로 수정하세요. 기록 반영 후 상단 **변경사항 저장**으로 보관하며 초안·이전 저장 기록·백업·JSON 내보내기에 함께 포함됩니다.

## 처음 입력할 때 확인할 것

- **전세보증금은 대출을 포함한 반환 총액**을 입력하고, 갚을 전세대출 원금은 별도로 입력합니다. 새 계획에서 상환 후 남는 내 자금을 보여줍니다.
- **전세대출 이자는 매월 납부액**입니다. 생활비와 별도로 입력하면 전세대출 상환일까지 월 지출에 반영합니다. 생활비·주거비에 이미 넣은 이자를 다시 더하지 마세요.
- **기간별 지출**로 퇴거 전 주거비, 입주 후 생활비, 출산 후 양육비 등을 나눌 수 있습니다. 월중 시작·종료와 포함된 이자·관리비도 구분합니다.
- **매수 비용**은 자동 계산 또는 직접 입력합니다. 법무사 견적에 포함된 세금·등기 비용을 중복 입력하지 마세요. 새 계획의 비용 검토 단계에서 재계산하고 항목별 내역을 확인할 수 있습니다.
- **금액은 단위를 선택**해 입력합니다. 변동자산은 보수적·공격적 예상액을 따로 넣고 계산 기준을 선택할 수 있습니다.

새 계획은 한국 시간 **오늘부터 계산**하도록 시작합니다. 보유 자금 기준일은 금액을 확인한 날이며, 그 이후 입력한 입출금을 반영해 오늘의 시작 현금을 계산합니다. 은행 실제 잔액을 자동 조회하는 기능은 아닙니다.

날짜별 **보유 현금에는 대출금이 포함**됩니다. 남은 빚과 `현금 − 빚`을 함께 확인하세요. 반환 전 보증금이나 주택 가치는 이 현금 잔고에 포함되지 않습니다. 월 유지비의 연 비용·보유세 월평균과 실제 납부일의 출금은 구분해서 표시합니다.

## 저장·백업·친구에게 전달

**변경사항 저장**은 미리보기와 확인 후 계획·변경 이력에 보관합니다. 이전 버전은 저장 기록에서 복원할 수 있습니다. 미저장 초안은 브라우저에 임시 보관하며 다시 열 때 복구할 수 있습니다.

Windows의 기본 자동 백업은 `data/backups`에 생성됩니다. **백업·복구**에서 독립 백업 파일과 저장 폴더를 지정하고, 내용을 확인한 뒤 선택한 계획을 복구할 수 있습니다. JSON 내보내기·가져오기도 지원합니다.

친구에게는 **Releases에서 받은 원본 ZIP**이나 웹 주소를 전달하세요. 사용 후 `data`가 생긴 앱 폴더를 통째로 보내면 본인의 계획·백업·프로필도 함께 전달될 수 있습니다. 공개 배포 ZIP에는 전달자의 개인 데이터가 없으며, 친구는 빈 계획에서 시작합니다.

## 자동 업데이트

**Windows 0.6.1 이상**은 앱을 먼저 연 다음 새 배포본을 백그라운드에서 자동으로 내려받아 검증합니다. 편집 중이거나 입력창이 열려 있으면 적용을 미루고, 저장하거나 입력창을 닫으면 자동 적용합니다. 다음 실행에서도 준비된 새 버전을 사용합니다.

새 프로그램은 `versions`에 따로 설치하고, 기존 **데이터·저장 이력·브라우저 프로필을 유지**합니다. 적용 전 DB를 백업하며 새 버전 실행에 실패하면 기존 프로그램으로 돌아갑니다. **GitHub 접속이 막히거나 확인에 실패하면 업데이트만 건너뛰고 기존 앱을 계속 사용합니다.** `업데이트 없이 실행.cmd`로 확인을 생략할 수도 있습니다.

웹도 새 배포를 확인해 편집 중이 아닐 때 자동 갱신하며, 브라우저에 저장한 계획을 유지합니다.

### 소스 버전과 앱 버전이 다를 때

앱의 **새 버전 확인**은 Git 커밋이 아니라 **Releases에 게시된 정식 배포본**을 확인합니다. `main`의 버전만 올려도 앱이 업데이트되지는 않습니다. 배포 게시 자체는 관리자가 검증 후 수동으로 진행합니다.

0.4.1~0.6.0의 다운로드 전용 앱은 한 번 프로그램 파일을 교체해야 합니다. 편집 내용을 저장하고 앱을 닫은 뒤, 새 ZIP의 프로그램 파일을 기존 `HomePlan` 폴더에 복사하되 **기존 `data`는 유지**하세요. 이후부터 자동 업데이트합니다. 새 폴더에서 실행하면 그 폴더의 빈 계획이 열립니다.

화면 준비가 실패하면 재시도와 **진단 파일 저장**을 사용할 수 있습니다. 진단에는 브라우저 정보와 초기 오류를 담고 금융 입력은 담지 않습니다. Windows에서 실행 파일 자체가 차단되면 앱 화면도 열리지 않을 수 있습니다.

## 개발자용: 소스로 실행

아래 명령은 소스를 수정·검증하는 개발자용입니다. 위의 Windows 배포본과 웹 사용에는 필요하지 않습니다.

Python 환경 관리 도구 [uv 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)를 참고한 뒤 프로젝트 폴더에서 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup_local.ps1
```

소스 업데이트 시에는 입력을 저장하고 `data`를 유지한 상태에서 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup_local.ps1 -Update
```

### 검증

```powershell
uv run ruff check .
uv run ruff format --check .
uv run mypy src/homeplan
uv run pytest -q
node --test tests/web/test_form_inputs.mjs tests/web/test_fund_builder.mjs tests/web/test_permit_tracking.mjs
uv run python tools/check_web_upgrade.py
```

테스트는 가상 입력과 독립 DB를 사용합니다. 개인 DB·엑셀·백업·프로필·개인 검토 자료는 커밋하거나 배포에 포함하지 않습니다. 금융 규칙의 적용 범위·출처·확인일은 앱의 **계산 기준·출처**에서 확인할 수 있습니다.

### 빌드와 수동 게시

```powershell
uv run --group build python tools/build_friend_package.py
uv run --group build python tools/build_pages.py
uv run --group build python tools/check_friend_package.py "dist/전달용.zip"
uv run --group build python tools/publish_local.py --windows --pages
```

원격 `main`의 최신 소스를 받아 검증·빌드한 뒤 게시합니다. 게시 도구는 오래된 소스나 더 낮은 버전을 최신 배포로 지정하는 작업을 거부합니다. `main` push 자체는 자동 배포하지 않습니다.

Windows 릴리스에는 프로그램 ZIP, `SHA256SUMS.txt`, 기존 0.4.0 업데이트 호환용 `release.json`을 첨부합니다. 실행 후 데이터가 생긴 폴더가 아닌 최초의 깨끗한 ZIP을 배포하세요.
